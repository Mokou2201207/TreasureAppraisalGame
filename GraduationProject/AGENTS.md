# AI開発・対話ルール (AI Interaction Rules)

## 1. プログラムコードのコメントルール
- **元々書かれていたコメントの維持**:
  - もともとコード内に存在していたコメントやコメントアウトは、勝手に書き換えたり新規に付け加えたりしない。
- **新しく書くコードのコメント**:
  - 関数の上には `/// <summary>` で、その関数が何をするかを書く。
  - 関数の中にも、処理のまとまりごとに「この処理は何をしているか」のコメントを書く（1行ごとには付けない）。
  - 文章はユーザーのコメントの書き方に合わせる。
    - 関数の説明は「〜する処理」「〜用の関数」「更新処理」のように短くまとめる。
    - 中のコメントは「〜したら〜する」「〜をセット」「〜へ」「nullチェック」のような短い言い方にする。
    - 「持ってる」のような、ふだんの話し言葉の言い方でよい。
- **コメント内の番号表記の禁止**:
  - コメントを記述する際、「1.」「2.」などの番号（箇条書き数字）は付けない。

## 2. 会話・言語に関するルール
- **完全日本語対応**:
  - 説明、回答、選択肢の提示を含め、会話はすべて日本語で行う。
- **英語の原則禁止**:
  - ユーザーが英語で質問した場合を除き、英語の使用は禁止。
  - どうしても英単語や英語表記を使いたい・使う必要がある場合は、あらかじめユーザーに許可を取ること。
- **英語のままでよいもの（許可済み）**:
  - 画面のボタン名（GitHub などのツールの画面に表示される名前）
  - Unity の機能名
  - プログラムの中の名前（クラス名・変数名・ファイル名など）
  - Unity のアセットについて聞くときの検索語やアセット名（アセットストアの検索語など）

## 3. プログラムの編集に関するルール
- **AIが編集してよいスクリプト**:
  - 体験版を作るため、`Assets/Script` の中のスクリプトは、すべてAIが書いたり修正したりしてよい。
  - 書きかえる前には、必ずそのときのファイルの中身を読んでから直す（ユーザーが途中で直していることがあるため）。
- **質問のときは編集しない**:
  - ユーザーがプログラムについて質問しているだけのときは、回答や説明のみ行い、ファイルを勝手に書き換えない。

## 4. モデル作りに関するルール
- **モデルを作るときはプレハブも同時に作る**:
  - AIがモデルを作ったときは、モデルだけで終わらせず、マテリアルを付けたプレハブまで必ず用意する。
  - モデルとテクスチャーは `Assets/Model/モデル名/` に、プレハブは `Assets/Prefab/Model/` に置く。
  - テクスチャーの名前は「モデル名_Albedo」「モデル名_Normal」にそろえる（`ModelPrefabMaker.cs` がこの名前でマテリアルを作る）。

## 5. 素材をプロジェクトに入れるときのルール
- **入れる前に必ず確認を取る**:
  - モデル・テクスチャー・SE・画像などの素材を作ったら、まずユーザーに見せて（聞いてもらって）確認を取る。
  - ユーザーが「OK」と言うまでは、Unityのプロジェクトに入れない。
  - 作り直したときも同じで、新しい版を見せてOKをもらってから入れかえる。
